Do published 3D-vision results survive a shared evaluation harness?

Plumbline is a reproducibility study of depth and camera-pose evaluation. It reconstructs the protocols behind reported numbers, reruns public models, and records both matches and failures without collapsing them into a leaderboard.

A “paper match” is one primary metric whose target was read directly from the source PDF and whose full recorded run falls within a declared tolerance. Companion metrics never inflate the count.

01 / research question

The number is not the protocol.

A benchmark value is the endpoint of a long, often underspecified chain: checkpoint, input resize, dataset selection, crop, valid mask, alignment, aggregation, and metric implementation.

Working hypothesis

Many apparent model differences—and many failed reproductions—are caused by evaluation choices rather than model quality. A useful comparison must expose those choices as data.

Plumbline tests this by expressing protocols as versioned configurations, sharing metric code across methods, and retaining discrepancies as findings.

02 / findings so far

Reproduction is possible—but rarely automatic.

A

Protocol details move results materially.

Median estimator variants, depth-vs-disparity alignment, crops, frame sets, and aggregation rules can decide whether a public checkpoint reproduces its paper.

B

Negative results are evidence.

When a released checkpoint remains off-paper after an audited implementation, the result stays visible as upstream-blocked or off-paper—not tuned into a check mark.

C

One scalar is not enough for tracking.

ATE and pose AUC can hide jitter, local failure, recovery, and coverage. The study now adds blinded pairwise trajectory review with human/VLM calibration.

03 / method

From paper claim to auditable result.

  1. 01

    Read the primary source

    Record table, row, column, metric direction, target, and tolerance from the PDF—not a secondary benchmark list.

  2. 02

    Reconstruct the protocol

    Pin checkpoint, dataset records, preprocessing, alignment, masks, metric implementation, and aggregation in YAML.

  3. 03

    Run the full evaluation

    Cache raw predictions before alignment, preserve environment metadata, and reject partial runs below the declared sample floor.

  4. 04

    Classify the evidence

    Promote only full runs within tolerance. Keep mismatches, private-recipe gaps, and informational comparisons visibly separate.

06 / reproduce & cite

The code is an instrument for the study.

Run a pinned experiment, inspect its exact configuration, or contribute a protocol correction. Most model runs require CUDA; the evidence and configuration ledger do not.

$ pip install plumbline-bench
$ plumbline reproduce da-v2-large-nyuv2
